# 蜂巢 UI 产品说明

第二轮体验版 · 2026-11-22

蜂巢（Fengchao）是 FileCodeBox 的公开存取界面。分享者存入一段文本或一组文件，拿到一个取件码。接收者凭码读取文本或下载文件。

## 本地体验

打开 [蜂巢首页](http://127.0.0.1:5173/#/)。本机 FastAPI 使用独立的临时数据目录，可以生成取件码并实际存取。示例分享链接和二维码指向本机地址。 [前端开发说明](README.md)

| 体验路径 | 操作 |
| --- | --- |
| 首页 | 比较「存」的纸飞机和「取」的开箱向上箭头图标，点击整张卡片进入。 |
| 存件 | 在[存件页](http://127.0.0.1:5173/#/send)输入一行字，观察文本框横向展开，以及有效期和提交按钮的位置。 |
| 存件结果 | 提交成功后，分别点取件码旁的复制图标、「下载命令」右上角的复制图标和底部「复制取件链接」。手动选中代码，核对显示与复制内容，观察页面顶部的提示。 |
| 取件 | 打开[示例文本](http://127.0.0.1:5173/#/retrieve?code=Y5NP0)、[示例 ZIP](http://127.0.0.1:5173/#/retrieve?code=OF653)或[非五位码示例](http://127.0.0.1:5173/#/retrieve?code=Demo-%E5%8F%96-7)，点「立即提取」。也可在[空白取件页](http://127.0.0.1:5173/#/retrieve)用数字键盘或 ABC 字母键盘输入，也可以粘贴取件码。 |
| 存取记录 | 在同一标签页交替完成一次存件和一次取件，从任一公开页面的页脚打开「存取记录」，核对顺序。带草稿打开再关闭记录抽屉，检查草稿。 |

## 页面和交互约定

### 首页

「存」和「取」是等权入口。卡片以纸飞机和带向上箭头的开箱图标为视觉焦点，其次是动作文字。「你要做什么？」与卡片说明降低视觉比重。整张卡片可点击，公共页脚提供「存取记录」入口。 [首页](src/views/HomeView.vue) · [公共布局](src/components/common/PublicLayout.vue)

### 存件与结果

- 空白时并排展示文本和文件。输入文本或加入文件后，当前区域扩展到整行，另一侧退出布局。清空后恢复两个区域。有效期和生成按钮跟在内容区后面。文件支持选择、拖放、追加和逐个移除。多文件在浏览器内打包为一个 ZIP，共用一个取件码。 [存件页](src/views/SendFileView.vue) · [存件流程](src/composables/useSendFlow.ts)
- 站点设置控制游客上传、文件大小和类型，以及可用的有效期方式。有效期默认取第一种可用方式，值为 1。在存件页开关记录抽屉时保留文本、文件和有效期草稿。离开存件页会尝试中止正在提交的客户端请求。 [存件流程](src/composables/useSendFlow.ts)
- 生成成功后清空草稿并打开原版「文件详情」。取件码旁的图标用于复制，二维码保留原位置，「复制取件链接」位于底部。「下载命令」在原命令区域内以代码块呈现，内容可以选中或横向滚动，右上角按钮复制完整命令。复制及其他操作提示沿用页面顶部的自动消失提示。 [结果弹窗](src/components/common/SentRecordDetailModal.vue) · [下载命令](src/utils/share-url.ts)

### 取件

- 取件码使用一个大输入框，光标固定在末尾。屏幕键盘、实体键盘和粘贴输入中的英文字母会转为大写，退格删除末尾字符。分享链接的预填值保留原大小写。去掉首尾空白后至少有 5 个字符时，才可点击「立即提取」或按 Enter 提交。输入框使用「输入取件码」文案，前端支持输入更长的码，由后端验证是否有效。 [取件表单](src/components/common/RetrieveForm.vue) · [取件流程](src/composables/useRetrieveFlow.ts) · [后台改码](../apps/admin/services.py)
- 数字键盘进入页面即可使用。ABC 原地切换至字母键盘，键盘铺满页面可用宽度，窄屏保留两侧各 8 px 的边距。最上排是 1–0，下方是 A–Z，额外提供退格和切回数字的 123 按键。新旧分享链接均预填，点击「立即提取」或在输入框按 Enter 后才取件。失败时保留当前内容，编辑后清除旧错误。 [路由](src/router/index.ts) · [取件表单](src/components/common/RetrieveForm.vue)
- 文本取件成功后直接打开 Markdown 预览并支持复制原文。文件打开详情，提供下载与适用格式的预览。限次文本在成功取件时扣减次数，限次文件在请求下载地址时扣减。 [取件结果](src/components/common/ReceivedRecordDialogs.vue) · [计次规则](../apps/base/views.py)

### 存取记录

- 首页、存件页和取件页的公共页脚打开原版右侧记录抽屉，当前页面原地保留。存件和取件共用一份列表，按操作时间从新到旧混排。每行展示名称、时间和大小，点击条目打开对应详情。 [记录抽屉](src/components/common/TransferHistoryDrawer.vue) · [记录排序](src/stores/fileData.ts)
- 记录保存在当前标签页内，刷新后清空。移除只影响当前列表。再次取回同一个码会更新该码的取件记录。可以用关闭按钮或点击遮罩关闭抽屉。 [记录状态](src/stores/fileData.ts) · [取件流程](src/composables/useRetrieveFlow.ts)

## 后续体验议题

| 场景 | 需要决定的行为 |
| --- | --- |
| 限次取件 | 文件预览与下载共用地址，预览可能消耗最后一次机会。是否先展示名称、大小和剩余次数，再让用户确认取件？ |
| 离开与上传 | 存件页开关记录抽屉时保留草稿。直接返回首页时是否也应恢复草稿？上传中应如何表达取消和服务端是否已生成分享？ |
| 文件组与有效期 | 是否要改 ZIP 包名？限额与有效期应该何时提示？当前默认配置下，后端对按时间计算的分享有 7 天上限。 |
| 历史保留期限 | 跨刷新时是否保留记录？如果保留，哪些字段应进入浏览器存储？下载地址失效后，是否从历史详情提供重新取件？ |
| 站点配置 | 站点背景已由公开配置返回，公共布局当前未使用。是否为主题增加背景入口？ |

## 回归检查

- 桌面和窄屏分别检查首页视觉层级，输入一行字后核对编辑区及主按钮位置。
- 分别用鼠标和键盘复制取件码、链接和命令。核对命令可选中、可滚动，显示与剪贴板一致。
- 用标准码、非 5 位自定义码、新旧链接完成取件。核对数字键盘直接展示、ABC 与 123 原位切换、输入大写且光标固定末尾。
- 在同一标签页交替存、取后检查记录倒序、详情和移除。在带草稿的存件页开关抽屉，确认内容与有效期保留。
